# Phase Targets

Concrete benchmark targets for each phase of the Security Champions program. Use these as starting points — adjust based on your organization's baseline, engineering culture, and program maturity.

These targets are not pass/fail thresholds. They are calibration tools. A program consistently below target in an area has a signal to act on. A program consistently above target has room to raise the bar or accelerate phase progression.

> **How to use this document:** Review targets at the start of each phase, set your specific organizational targets in the rightmost column, and review at the phase gate before advancing.

### Phase 1 Gate Criteria

All of the following must be met before advancing to Phase 2:

- [ ] Manager approval rate ≥ 90%
- [ ] 90-day champion retention ≥ 80%
- [ ] At least 40% of low/medium findings triaged by champions
- [ ] Manager feedback net positive
- [ ] No unresolved organizational resistance blocking program expansion
- [ ] At least 70% of champions have completed core training

## Setting Your Own Targets

These benchmarks are based on observed program patterns across mid-to-large engineering organizations. Adjust based on:

**Adjust targets down if:**
- This is a first-ever Security Champions program with no prior foundation
- Engineering and security have a historically adversarial relationship
- Manager buy-in required significant effort to secure
- Your security team has limited capacity to support champions

**Adjust targets up if:**
- You are relaunching a program with an existing champion community to build on
- Engineering leadership is actively championing the program
- Your organization has strong DevSecOps foundations already in place
- You have dedicated program management capacity

**Never adjust the gate criteria without documentation.** If you advance a phase while gate criteria are in risk signal range, document why — it creates organizational accountability and prevents the quiet slippage that causes programs to stall.
